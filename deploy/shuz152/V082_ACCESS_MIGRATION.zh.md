## 权限映射

| 旧实现 | 官方实现与迁移规则 |
| --- | --- |
| `access_restricted=false` | `visibility='workspace'`，仍对工作区成员可见 |
| `access_restricted=true` | `visibility='private'`，不变为公开项目 |
| `created_by` | 已知创建者迁为 `creator_type='member'`、`creator_id`，并写入 `project_member`，保留原有访问权 |
| `allowed_user_ids` | 逐一写入同一工作区、同一项目的 `project_member`；去重，创建者不必原本在数组内 |
| 已离开工作区的历史授权 | 保留原授权记录；平台仍要求工作区成员身份，不恢复已离职成员的实际访问权 |
| 未知历史创建者 | 不猜测，不用负责人或工作区所有者代填 |
| 旧权限入口、`/access` 接口、查询和实时过滤 | 删除，统一使用官方访问模型和成员接口 |

保留旧数据库字段作为回滚数据，不进行双写，也不参与新版的访问判断。公开项目原来存储的休眠授权名单同样保留，避免丢失数据。

### 官方语义差异

- 工作区 owner/admin 可查看所有私有项目，普通成员须有项目成员记录。这是官方规则，与旧版“管理员也须被创建者授权”不同。
- 权限管理由工作区 owner/admin 或私有项目的人类负责人负责；旧创建者保留访问权，不额外伪造负责人或保留第二套管理规则。
- Agent 运行按发起人和 Agent 所有者共同约束访问，撤掉旧版 task token 对项目限制的统一绕过。不为运行端自动扩大人类授权；需要覆盖此边界的回归。
- 不把原先没有授权的普通项目负责人自动加入成员表，以免借迁移扩大普通成员权限。

1. 原受限项目仍为私有，原创建者和全部授权成员可访问；未授权普通成员访问项目、任务、评论、附件、搜索与实时事件均不可泄露信息。

4. SQL 测试覆盖重复名单、创建者不在名单、多工作区、公开项目休眠名单，以及切换后增删授权再回滚；文件为 `server/internal/migrations/testdata/fork_project_access_to_official.sql`。

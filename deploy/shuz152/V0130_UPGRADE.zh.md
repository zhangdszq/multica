# SHUZ-158 v0.13.0 升级技术设计

## 目标与审批范围

将已部署的 v0.11.1 升级至 [官方稳定版 v0.13.0](https://github.com/multica-ai/multica/releases/tag/v0.13.0)。上游 tag 提交为 `35b54a3742bb51bdf5ffa688655367ec98044862`，fork 基线为 `cdbd7a93e40d5bab5ee39c4c20596d46dfb300d0`。

本批拟应用 **59 项数据库迁移，fork 703–761，对应官方 697–755**。本批包含表结构变更，按工作区 AGENTS.md 需要人工审批后才可修改业务测试库。正式库的操作也以本次批准的迁移批次和上线范围为准。上一版本的审批仅覆盖 643–702。

新增 118 个 up/down SQL 文件的 SHA-256 为 `c1d65809d407bf9403de412498c9150af9683700940bcebc2ed703c72fdfb499`。计算方式为按文件名排序，依次拼接文件名、NUL 字节和原始内容后取摘要。候选保留 fork 已有迁移文件，重编号只用于新增 SQL。运行器、并发索引清理和跨包测试里的完整迁移名同步调整。

## 迁移内容与数据风险

| Fork 编号 | 主要内容 | 验收重点 |
| --- | --- | --- |
| 703–708 | 自动化运行幂等键、访客邀请范围、成员搜索授权版本 | 私有项目原有授权逐条对比；授权变更后本地搜索可以刷新 |
| 709–724 | 文档评论及协作版本、附件大小索引、面板时间范围、归档提示 | 附件原文件与下载权限；验证索引有效和文档功能开关 |
| 725–736 |远程应用账户、任务正文协作版本、团队账户请求及通知偏好 | 已有账户可用；协作关闭时任务正文仍可保存 |
| 737–748 | Skill 版本、评论幂等回执及小队用量聚合 | 评论重试不重复；旧用量与刷新后的小时数据一致 |
| 749–761 | 任务阻塞关系及阶段唤醒、直接交接、应用用量及评论运行、小时聚合修正 | 依赖和阶段唤醒按条件触发；用量按小时聚合且保留旧数据 |

聚合迁移 745 会替换旧唯一约束并调整聚合函数。761 在脏小时重算时按完整小时更新各小队与独立任务的用量。迁移演练必须覆盖已有用量、重算后的总额及旧应用在新库上的读写兼容性。反向迁移可能清除新表数据、撤销文档与任务正文版本、移除阻塞关系和账户请求。上线开放写入后，在确定数据恢复点和补偿方案前不得执行批量 down 或覆盖库快照。

## 需要保留的业务行为

- 保留任务正文窄、正常、宽三档和图片排列设置，同时保留新版的访客只读、协作编辑和附件绑定逻辑。
- 项目访问继续使用官方授权模型。 642 已迁移的成员授权、私有标记和创建者应逐条匹配。旧授权桥接不在此次部署中重跑。
- 在正式 Compose 里保留现有微信加密密钥，禁止轮换或输出到日志。核对上线前后的微信功能开关、连接状态和后端对 iLink 的出站访问。已绑定连接可用 `/help` 做收发验收。扫码由账号本人完成。
- 知识库和正文实时协作沿用现有开关。官方默认关闭，独立加开功能前需验证相应协作服务。
- 保留附件下载的调用方超时语义。升级服务器容器不包含成员电脑上的运行端与 CLI 替换。

## 备份、上线与回退

1. 重新登录阿里云 `szxh` CLI profile。以只读 ECS 请求确认凭据可用，再核对部署镜像、业务库迁移清单、表及积分用量状态。记录项目可见性、成员授权以及微信状态的聚合计数和摘要。备份目录和输出必须仅管理员可读，密钥与数据库备份不得上传到 PR 或评论。
2. 从业务库备份恢复到独立测试副本后应用 703–761，再执行第二次 `up`。核对授权、旧任务和附件、应用账户、旧版用量及所有新索引。验证 v0.11.1 后端能否在扩展后的库上正常处理读写，尤其是用量聚合相关路径。
3. 先部署测试环境，使用固定候选镜像完成浏览器验收。覆盖任务编辑和宽度、图片、访客访问、附件、任务阻塞关系和启动状态。捕获候选截图，适用 CI 通过后合并。合并前重查 `origin/main` 的迁移编号。
4. 正式切换前停止应用写入，备份数据库并验证 `pg_restore -l`、记录 SHA-256。保存旧镜像和完整 Compose，核对停写时的授权摘要。应用同批迁移后比较项目权限快照，再启动已在测试验收的镜像。验证 `/health` 和 `/readyz`、正式页面、附件与微信，查看容器重启和错误日志。
5. 写入恢复前若出现故障，使用停写快照和旧镜像恢复服务。写入恢复后若需回退，先备份当时的库。只有在副本实测旧版兼容时才可仅回退镜像。若需数据库恢复，先核对切换后的数据增量与补偿方案。

## 当前上线条件

上线前需要批准 703–761 迁移。发起 ECS 只读复查时，阿里云 `szxh` profile 的 OAuth 令牌刷新返回 HTTP 400，需要重新登录后方能执行业务库预检与备份。候选代码及独立测试可以先完成。本文件记录升级设计，实际发布以测试和正式环境的验收记录为准。

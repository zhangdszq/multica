# SHUZ-152 未授权项目完全隐藏技术设计

## 结论

项目开启限制访问后，未被授权的工作区成员应把该项目视为不存在：列表与搜索不返回项目，已知 UUID 的直链返回 `404`，项目任务、资源、收藏和实时消息也不应暴露项目存在性。项目创建人和被选中成员的行为保持不变。

本次不修改数据库结构和既有授权数据，只收紧读取语义及客户端缓存失效行为。尚未开启限制的项目仍保持工作区内公开。

## 权限判定

服务端继续以请求凭据对应的用户 ID 为唯一主体，规则如下：

1. `access_restricted=false`：工作区成员可访问。
2. `access_restricted=true` 且当前用户是项目创建人：可访问。
3. `access_restricted=true` 且当前用户在 `allowed_user_ids`：可访问。
4. 其他情况：按项目不存在处理；`owner`、`admin` 不自动绕过。

权限必须在服务端执行。手机客户端仍需使用每位用户自己的 Bearer Token；共享高权限 Token 无法区分真实用户，不在该权限模型的保护范围内。

## API 行为

| 入口 | 未授权行为 |
| --- | --- |
| `GET /api/projects` | 过滤整条项目记录，`total` 只统计当前用户可见项目 |
| `GET /api/projects/search` | SQL 层过滤，不参与匹配和分页 |
| `GET /api/projects/{id}` | 返回 `404 project not found` |
| 项目修改、删除、资源接口 | 返回 `404`，不区分不存在与无权访问 |
| 项目下任务详情与修改 | 返回 `404`；任务列表、搜索、表格查询继续在 SQL 层过滤 |
| 项目/任务收藏 | 列表过滤历史收藏；新建收藏返回 `404` |
| 附件、聊天上下文、自动化 | 沿用既有项目权限校验，不返回受限内容 |

保留 `access_allowed` 响应字段是为了兼容已经安装的客户端，但服务端不再向未授权请求返回 `access_allowed=false` 的项目占位对象。

## 实时同步与缓存

权限变更时服务端发送两类互斥事件：

- 仍有访问权的接收者收到标准 `project:updated`，携带正常项目数据。
- 已失去访问权的接收者收到 `project:access_changed`，负载只有 `project_id`，不包含标题、描述、授权名单或其他项目字段。

实时消息授权器在投递时重新查询当前权限，确保同一连接不能在撤权后继续接收项目内容。手机客户端收到 `project:access_changed` 后立即移除项目列表、详情和资源缓存；若用户正停留在详情页，按项目删除同等方式退出页面。

断线期间错过事件时，重连后的既有项目列表刷新仍会以服务端过滤结果为准。

## 兼容性与风险

- 不新增迁移，不改变现有 `access_restricted` 或 `allowed_user_ids`。
- 旧客户端收到的项目列表已经由服务端过滤，因此不会显示受限标题。
- 直接访问从 `403` 改为 `404`，调用方不能再依赖“找创建人授权”的错误文案；这是“项目不存在”语义的必要变化。
- 历史本地缓存只能在客户端收到实时事件、重新连接或重新请求后清理；服务端无法删除设备上已经离线保存的数据。
- 项目创建人修改授权的能力不变；未授权用户调用授权管理接口也返回 `404`，避免借此探测项目。

## 验收标准

1. 普通成员和未被选中的管理员在项目列表、项目搜索中都看不到受限项目 ID 与标题。
2. 使用项目 UUID、任务 UUID、资源或收藏接口探测时均得不到项目存在性或内容。
3. 创建人和被授权成员仍能正常读取项目、任务和资源。
4. 撤销授权后，HTTP 请求立即失败，WebSocket 不再投递项目内容，手机客户端清除缓存并退出详情页。
5. 重新开放项目后，工作区成员恢复正常访问。

## 测试与回退

核心回归由 `TestProjectAccessLifecycle` 覆盖列表、搜索、详情、资源、任务、表格、收藏、管理员边界和 WebSocket 分流。TypeScript 类型检查覆盖新增事件契约与手机客户端订阅。

回退只需恢复本次应用代码；数据库无结构或数据变更，不需要数据库回滚。回退后会恢复此前“标题可发现、内容受限”的行为。
